# DECISIONS — Hotel Metasearch Production-Readiness

Техническая память: доказанные первопричины, эксперименты, архитектурные решения.
Формат: факт → доказательство → вывод. Не журнал команд.

## D1. Flaky beach-тест `test_beach_search_uses_city_and_country_slugs` (2026-10-13)

- **Факт:** падал ~9/10 в пределах одного файла `tests/test_hotel_search.py`, проходил
  изолированно. `IndexError` в `test_hotel_search.py:2292` = `calls[1]` (тест ждёт **два**
  photon-запроса; в наборе приходил один).
- **Первопричина (доказано):** модульно-глобальные кэши протекали между тестами процесса.
  `PHOTON_CITY_EXTENTS` (providers) греется любым ранним тестом, резолвящим тот же город →
  первый photon-запрос исчезает → `calls[1]` IndexError. Плюс глобальные Overpass-состояния
  (`_OVERPASS_ENDPOINT_COOLDOWNS`, failure streaks, `_OVERPASS_NEXT_START_AT`,
  `_OVERPASS_COOLDOWN_UNTIL`) от транспортных тестов: `_OverpassRequestDeferred` (наследник
  TimeoutError) глотается `_overpass_beach_features` → overpass-вызов исчезает.
- **Фикс:** `tests/conftest.py` autouse-фикстура: сохраняет и очищает globals до теста,
  восстанавливает после.
- **Результат:** 6/6 прогона файла, 3 полных набора 618 passed.
- **Открытый дефект (ТЗ п.16):** восстановление через `.update(saved)` неточно — элементы,
  добавленные самим тестом, остаются после teardown. Нужен точный rollback (очистка + запись
  ровно сохранённых). Оставлено как задача 2 реестра.

## D2. SQLite WAL (2026-10-13, коммит `1c011c6`)

- **Факт:** `journal_mode=delete` блокировал читателей на время записи: измерено 3 ошибки
  `database is locked` при одной транзакции.
- **Фикс:** `schema.py:_initialize_hotel_store_uncached` выполняет `PRAGMA journal_mode=WAL`
  при инициализации хранилища (безопасно пере-применяется к существующим БД).
- **Наблюдение 2026-10-14:** prod-БД `hot-tickets.sqlite3` на диске показывает
  `journal_mode=delete`. WAL применяется только при открытии через init-путь; файл,
  последний раз открытый старым кодом, не переключён. При следующем штатном запуске сервера
  init переведёт режим. Задача 3 — подтвердить live.
- **Вывод:** проверять `PRAGMA journal_mode` после живого прогона, а не по факту коммита.

## D3. VPN ломает Trip-навигацию (2026-10-13)

- **Факт:** с VPN Trip.com `commit` даёт HTTP 200 за ~554мс, но `domcontentloaded` не
  наступает (30с таймаут) даже на корневой странице. Без VPN: 735–959мс, всё живое.
- **Вывод:** smoke Trip.com только без VPN; зависание навигации при живом HTTP —
  диагностический признак туннеля, не антибота.

## D4. Geo_id-персистентность (2026-10-13, коммит `7cf348e`)

- **Факт:** resolution города зависел от живого suggest; при сбое город деградировал до
  trip-only без geo_id, хотя подтверждался часами раньше (Дананг флапался
  `geo_id=2658853` ↔ `null`).
- **Фикс:** `city_resolution.py` — подтверждённые items пишутся в `hotel_city_geo_cache`
  **только при явно заданном `HOT_TICKETS_DB_PATH`** (по умолчанию нет — защита prod-БД от
  тестовых городов; ранее было загрязнение, вычищено).
- **Проверка 2026-10-14:** в prod-БД таблицы нет → текущая реализация не пишет в prod. 
  Кросс-процессная работа (запись → перезапуск → чтение) — задача 4.

## D7. Delegate-провайдер `brataann` не существует (2026-10-13)

- `delegate_task` падает: «Cannot resolve delegation provider 'brataann'». Доступные:
  openrouter, nous, zai и др. При параллельной работе — либо починить конфиг, либо
  работать напрямую. Проверить заново при первой реальной потребности (задача 14).

## D9. Sravni не предоставляет room-вариантов (2026-10-14)

- **Факт:** `/api/v1/search` даёт offers[] по одной на провайдера (yandex/ostrovok/tutu);
  повторных офферов одного провайдера нет; hotel-rooms endpoint не существует.
- **Решение:** не имитировать альтернативные номера (спека §6). «Варианты» Sravni =
  цены разных OTA — уже показываются.

## D10. Exit code 3 сервера в smoke — контракт, не дефект (2026-10-14)

- **Механика:** harness шлёт `CTRL_BREAK_EVENT` в process group сервера; uvicorn на Windows
  обрабатывает SIGBREAK как graceful shutdown («Application shutdown complete. Finished
  server process» в логах), после чего процесс завершается с кодом 3 (Windows console
  control-event exit). Порты освобождаются, БД остаётся целой (integrity ok).
- **Вывод:** `server_exit_code: 3` в smoke-артефактах = штатное внешнее завершение.
  Дефектом не считать; менять код выхода ради «зелёного» отчёта не нужно (спека §15).

## D11. Кнопка отзывов Sravni — первопричина и фикс (2026-10-14, `36d97f9`)

- **Причина:** raw JSON Sravni содержит `canonical_url` (путь страницы отеля на
  hotels.travel.ru, живая страница с отзывами, HTTP 200), но нормализация его отбрасывала →
  `reviewLink()` во фронте не имел кандидатов для sravni-only карточек → кнопка не
  рендерилась («мёртвая»).
- **Фикс:** `normalize_hotel` → `source_hotel_url` (абсолютный passthrough или
  absolutized /path; мусор/javascript: отвергается), read_model прокидывает в API,
  `reviewLink()` пробует после явных review_url. Синтетические URL не строятся.
